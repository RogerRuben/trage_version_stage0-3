# C/M/A 交通状态适配假设草案（未实施）

状态：`DRAFT_NOT_DEPLOYED`。这里定义比较情境，不认证真实 AV 能力。
现有 `stage3_av_capability_profiles.json` 不变；没有将本文件接入 Stage4。

## 1. 两层输出，不把软状态变成物理禁行

结构层继续保留方向、明确禁止 movement 等约束。
交通层表达道路相对减速、低速暴露与不稳定性，供适配解释和政策比较。

拥堵通常影响服务时间和运行环境；HV 轨迹能够提供交通状态证据，但不能由此
证明某一代 AV 在拥堵下是否安全。因此下面的适配矩阵是明确的运营策略假设。
若未来选择禁止某类状态，应标为“该假设策略不接受”，不能写“AV无法安全通过”。

## 2. 嵌套目标环境

| 已知状态代理 | C | M | A |
|---|---|---|---|
| 非拥堵 | 目标环境内 | 目标环境内 | 目标环境内 |
| 拥堵 | 目标环境外暴露 | 目标环境内 | 目标环境内 |
| 严重拥堵 | 目标环境外暴露 | 目标环境外暴露 | 目标环境内 |
| MIXED_EVIDENCE | 需解释，不强行归档 | 同左 | 同左 |
| UNKNOWN | 证据不足 | 证据不足 | 证据不足 |

这延续用户提出的 C→非拥堵、M→扩展拥堵、A→再扩展严重拥堵的情境设计。
它不是数据估计出的“拥堵越强就必需更高级 AV”的普遍规律。
缓慢平稳排队与频繁起停的区别继续由独立的不稳定性描述解释。

## 3. 先保留暴露向量，再选择容忍政策

对未来决策时预测路线，使用冻结预测时间作为权重，分别输出：

- 非拥堵、拥堵、严重拥堵的预测时间占比；
- 混合证据和未知的预测时间占比（不得在分母中消失）；
- 最长连续拥堵/严重拥堵预测时长；
- reference 支持、模型来源、预测时点/进入时点与时距。

设占比分别为 s_free、s_cong、s_severe、s_mixed、s_unknown，五者和为 1。
目标环境外已知暴露可记为 U_C=s_cong+s_severe，U_M=s_severe，U_A=0。
最后一个 0 **仅表示在这张假设表中没有更高的已知拥堵等级**，绝非 A 总体可行，
也不能抵消未知、混合证据、静态约束、方向或速度域条件。

尚待决定：

1. 严格零暴露还是允许小范围环境外暴露；
2. 除占比外是否需要连续时长预算；
3. 混合证据的子类型是否需要区别；
4. 未知占比怎样影响可派单资格。

这些数值本批不从 Validation 通过率反向拟合。严格零暴露可以是一个待授权的
清晰对照，但不是本批默认生产策略；正预算也不能凭感觉填进 profile。

## 4. 与原 E/Q/C 的关系

原 crawl/stop 的 E/Q/C 与新状态的低速条件共享输入。直接把两套超限相加，
会把同一来源当成两份独立证据。建议分两阶段：

1. 近期作为解释层：保留冻结判定，新增状态/暴露解释，不增加惩罚。
2. 若后续授权独立方案：将拥堵状态暴露与原 crawl/stop E/Q/C 明确设计为替代
   或对照，而非无条件叠加；speed CV/acceleration 是否保留独立约束，由本批
   家族交叉表及后续研究选择决定，不因相关性而直接删除。

E 是全路线时间加权 CDF 均值，Q 是高尾时间占比，C 是最长连续高尾秒数；
它们不是三档交通状态。新状态包含相对 pace 信息，有不同语义，不应自动认为
完全冗余。反之，低相关也不能证明它能提高派单性能。

速度域描述道路速度环境，拥堵描述动态条件，二者不应互相替代。
