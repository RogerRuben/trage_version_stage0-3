# 武汉 Robotaxi 请求生命周期核对

## Material Passport

- Origin Skill: academic-research-suite / descriptive statistical validation
- Origin Date: 2026-09-25
- Verification Status: ANALYZED
- Version Label: request_lifecycle_v1
- 范围：公开处理样本的字段核对与描述统计；不是原始事件日志认证、patience估计或Stage4实验。

## 结论

**可用于说明请求释放与轨迹出发之间存在时间差；不可直接用于校准西安乘客耐心或接单模型。**

本轮进一步发现，公开文件已经经过处理，字段名称不足以证明原始事件含义。尤其“取消时间”“行程时长”不能按字面直接使用。上一轮所称“真实请求时间字段”应更准确理解为：**作者公开的Robotaxi处理样本中保留了命名为呼单时间等字段，而非本项目独立认证的未经变换运营日志。**

未修改西安参数、任何冻结profile、41场景或论文正文。没有运行作者代码、地图匹配、模型拟合、GPU任务或大矩阵运算。

## 2. 建议字段字典

以下是分析接口建议，不是修改现有产品schema。

| 原字段 | 建议分析名 | 当前能说什么 | 不能直接说什么 |
|---|---|---|---|
| 呼单时间 | request_time_reported | 样本报告的呼单时刻 | 原始服务器事件已经独立核实 |
| 接单时间 | acceptance_time_reported | 报告的接单时刻 | 与dispatch decision或乘客接受AV完全等价 |
| 出发接驾时间 | pickup_departure_time_reported | 报告的开始接驾时刻 | 全天availability起点 |
| 到达起点时间 | vehicle_arrival_time_reported | 报告的车辆到达上车点时刻 | 乘客已经上车 |
| 开始行程时间 | boarding_proxy_time | 上车/载客开始的代理 | 精确车门事件或GPS开始时刻 |
| 到达目的地时间 | destination_arrival_time_reported | 报告的目的地到达时刻 | 车辆立即空闲且可派 |
| 取消时间 | cancellation_field_unresolved | 字段存在，但事件语义未闭合 | 非空即发生取消 |
| 接驾时长 | pickup_duration_reported | 与出发接驾至到达起点差高度吻合 | request至pickup的总等待 |
| 行程时长 | duration_reported_unresolved | 更接近接单至目的地的总历时 | 纯载客旅行时间 |

作者拼车脚本在输入解析时将“到达起点时间”赋给 `call_time`。该内部时钟不应移植为我们的request release。证据路径：上游 `7-sample_data_and_code/carpooling_one_day_sample_code/run_carpooling_one_day.py`，解析v12字段的代码段。

## 3. 时间顺序与量化

七个时间字段全部可解析、无空白，均以分钟格式公开。六事件主链：

呼单 → 接单 → 出发接驾 → 到达起点 → 开始行程 → 到达目的地。

全部6,727行在这条链上非递减；这是内部顺序检查，不是外部真实性证明。

| 时间差 | P50 | P90 | P99 | 最大值 | 零差记录数 |
|---|---:|---:|---:|---:|---:|
| 呼单至接单 | 0s | 60s | 420s | 1,200s | 5,908 |
| 接单至出发接驾 | 0s | 0s | 60s | 240s | 6,093 |
| 出发接驾至车辆到达 | 300s | 660s | 1,080s | 2,160s | 233 |
| 车辆到达至开始行程 | 60s | 120s | 240s | 8,460s | 1,876 |
| 开始行程至目的地 | 780s | 1,620s | 3,300s | 6,300s | 157 |
| 呼单至车辆到达 | 300s | 720s | 1,200s | 2,220s | 178 |
| 呼单至开始行程 | 360s | 744s | 1,260s | 8,700s | 11 |

不能由大量0秒响应推断即时派单：分钟量化会掩盖亚分钟差异，具体是四舍五入、截断还是其他处理没有确认。也不能简单将60秒粒度的字段用于验证我们30秒epoch内的响应机制。

## 4. 字段陷阱与异常标记

### 4.1 “取消时间”不是可直接识别的取消事件

6,727条完成订单全部填有取消时间，4,159条与到达目的地时间相同。与此同时“取消次数”全部为0。

可确认的是字段组合需要解释，不能断定全部完成单发生取消，也不能断定它一定是哪个系统字段的拷贝。上游预处理包含取消单合并逻辑，但没有从公开文件完整恢复出这份样本的逐步处理血缘。

**因此本样本不能独立识别取消率、取消hazard或潜在patience。**

### 4.2 时长字段与事件差并非同一对象

采用绝对差≤60秒作为分钟精度下的描述性对照窗口，不是质量放行阈值：

- 接驾时长有6,290条数值，437条缺失；其中6,289/6,290与“出发接驾至到达起点”相差≤60秒，中位绝对差17秒。
- 行程时长与“开始行程至目的地”仅78/6,727相差≤60秒；与“接单至目的地”则为6,274/6,727，中位绝对差19秒。
- 行程时长有329条为0；其中328条的“开始行程至目的地”却为正。

这支持“接驾时长主要对应接驾移动阶段”“行程时长不是纯载客时间”的解释，但不能替代作者字段字典。比较多个时间差是探索性语义检查，不是通过拟合最接近列确立真值。没有据此改写原字段。

### 4.3 尾部和合并标记

- 6条记录的到达起点至开始行程超过30分钟，最大141分钟；5条请求至车辆到达超过30分钟。
- 486条“虚拟单合并数”大于1，6,241条等于1。该字段提示处理过程可能改变统计单位；并不直接证明486条都是拼车或取消重试。
- 两组的请求至到达P50均为300秒，请求至开始行程P50均为360秒；长上车等待尾部仍存在于marker=1组，不能把尾部全部归因于合并。
- 上述30分钟仅是明确标注的检查窗口，不是删除规则；所有统计保留全部行。

## 5. 描述性异质性

三种下单渠道的请求至车辆到达P50均为300秒、至开始行程P50均为360秒。这说明总体中位数不是仅由某一个渠道特有中位数驱动，但不构成渠道等价性检验。

小时分组有差异：17时和18时的请求至到达P50均420秒，而12时、15时和19时为240秒。夜间若干小时只有8–31单，不能把单日波动包装成稳定的时段规律。分组完整结果保存在CSV，没有只选择显著组，也没有做显著性检验。

402辆车每车记录数为1–34，中位17。这些订单不是6,727个独立同分布的乘客/运营环境重复实验。后续如做区间估计，应先明确按车、时段或日聚类；本轮没有为单日样本生成貌似精确的总体置信区间。

## 6. 对我们当前模型的含义

### 能支持

1. 在这份已完成运营样本中，request release与boarding proxy通常不重合，存在分钟级差异。西安zero-lead应继续显式标注为回放假设。
2. 总等待、接驾移动、车辆到达后的上车等待应分开。它们分别对应不同的控制变量与时间消耗。
3. 请求至上车代理的分布可以作为外部数量级参考，但必须保留“单城、单日、完成样本、已处理、分钟精度”的标签。

### 不能支持

1. 直接把300秒中位等待当作300秒patience的实证校准。
2. 因为3,045条完成订单请求至到达超过300秒（约45.3%），就推断我们的同等比例订单“本应被救回”。两地、时期、供给状态和样本选择均不同。
3. 把当前订单事后实现的等待时长输入该订单dispatch模型。它是结果变量，只可用于事后诊断或适当历史训练，不能成为decision-time泄漏。
4. 把“取消时间”非空当事件训练生存模型，或以完成订单等待分布估计所有请求的耐心分布。
5. 用报告的行程时长直接替换Stage1 travel-time标签或M3预测目标。

从识别角度，observed waiting time与maximum willingness to wait不同。完成条件、供给和派单共同筛选了样本；即便知道所有完成订单的等待，也没有识别取消/未匹配需求的耐心。下一步如需估计，应另获全请求台账、失败/取消事件、时间定义、抽样分母及删改规则。

## 7. 最小质量检查与解释审查

计算检查：唯一订单数与前轮清单一致；相邻事件时间差之和逐行精确等于总时间差；请求至到达P50/P90与前轮一致；开始行程P50一致。另用标准库csv/datetime独立重算6,727行、300秒中位数及3,045条超过300秒，结果一致。没有训练、路由、仿真或统计检验。

11类解释风险逐项检查（覆盖检查不等于证明风险不存在）：

| 风险 | 本轮处理 |
|---|---|
| Simpson反转 | 输出时段/渠道/合并标记分组；未估计组间因果关联，不声称排除所有混杂 |
| 生态谬误 | 不从总体分位数推断个体patience |
| Berkson选择 | 明确只有完成样本，外推受限 |
| Collider偏差 | completion可能共同受供给/等待/意愿影响；未将条件分布解释为因果 |
| 基础率忽略 | 无完整呼单分母，不估计取消/失败率 |
| 回归均值 | 无前后干预或改善结论，不适用 |
| 幸存者偏差 | 明确缺取消、未响应总体及抽样选择 |
| 多重搜寻 | 无显著性检验；全部预定义分组结果保留 |
| 分析自由度 | 描述性探索，未删异常、未择优校准；语义比较不认定真值 |
| 相关即因果 | 不把小时差异解释成AV机制或策略效果 |
| 反向因果/信息时序 | 事后等待不得输入当前订单决策；未作方向性回归 |

## 8. 完成与下一步边界

本阶段：REQUEST_LIFECYCLE_DESCRIPTIVE_AUDIT_COMPLETE。

字段可用性是混合结论：主事件顺序与有限精度下的描述统计可用；取消语义、纯载客时长字段、完整血缘和代表性仍未闭合。无需为这些缺口重跑西安。

下一步可做现有A/M/D/L的max/mean/tail只读描述诊断，先核对路线级组件与权重可用性；不自动引入SNE gate、不放松UNKNOWN、不修改Gamma，也不把该诊断写成匹配收益。本轮没有执行这一阶段。
