# 武汉公开空间活动与复杂度暴露：只读诊断

日期：2026-09-25。代码基线：`c143fc9`。没有修改论文、模型、冻结 profile 或任何调度场景；没有运行第三方脚本。原始工作簿保持不变。

## 1. 结论与边界

这些公开数据支持一个有用但有限的判断：**Robotaxi 与 HV 的已实现空间活动分布明显不同，且已完成行程的复杂度暴露也不同。它们不能单独识别能力约束、服务区限制、需求构成和平台选择各自的作用。**

尤其不能把活动为零当成 AV 不能通行，也不能把两个边际分布拼成“复杂度导致订单流失”的因果证据。对本项目的价值是把 service-domain selection 与 conditional operational compatibility 分开，而非增加一个未经验证的硬门。

## 3. Figure 2：先确认统计对象

三个表块共有 2,651,616 个唯一 grid×hour 单元，恰等于 3,564 网格×744 小时。无重复键、无部分缺失行；第三表块末尾 348,384 行是空白填充，不是零观测。订单总数与工作簿控制数完全一致：Robotaxi 258,363，HV 3,500,485。

发布时轴为 2024-11-12 至 2024-12-12，共31天。然而 HV 正计数仅出现在前21个日期；12月3日至12日 HV 总数全为0。作者 fig2b 将 HV 的第 n 个观测日映射到 AV 的第 n 个观测日，同时展开网格×小时并填零。因此：

1. 发布日期不证明两类数据实际同日。
2. 完整矩形表不等于两类原始数据的观测窗口相等。
3. 后10天的零不能解释为真实 HV 停止运营。
4. AV 使用呼单时间、HV 使用 start_time；时间语义也不完全等价。

统计保留全表以便对账，并额外输出双方日总计数均为正的21个**对齐日期**对照；这只是覆盖敏感性检查，不恢复真实日历同步，也不证明每个零是可靠观测。

### 全发布窗口的空间活动

| 指标 | 结果 | 解释 |
|---|---:|---|
| Robotaxi 正活动网格 | 900 | 至少一次正计数，不是服务区边界 |
| HV 正活动网格 | 2,103 | 同上 |
| 两者均有活动 | 819 | 跨窗口聚合，不要求同时发生 |
| 任一模式有活动 | 2,184 | 活动并集 |
| 活动网格 Jaccard | 37.50% | 819 / 2,184 |
| Robotaxi 订单落在共享活动网格 | 95.90% | 按 Robotaxi 订单量加权 |
| HV 订单落在共享活动网格 | 35.22% | 按 HV 订单量加权 |
| 归一化空间分布重叠 | 16.31% | 各模式计数各自归一化后，逐网格取最小值再求和 |

“Robotaxi 大部分订单位于 HV 也活动的网格”与“两个模式的订单密度分布重叠较低”并不矛盾：支持集共享不代表权重相似。窗口长度不同也会影响上述描述，不能将其作为调整后的模式效应。

全表 grid×hour 状态：双零 2,277,469，HV 单独正值 260,921，双方正值 38,162，Robotaxi 单独正值 75,064。后者尤其受后10天 HV 全零影响。逐小时结果也只是在同一钟点跨日期汇总，不是瞬时竞争图。

在双方日总计数均为正的21个对齐日期中：Robotaxi 167,094 单；HV 仍为3,500,485单。Robotaxi 活动网格865个、共享792个、并集2,176个；Jaccard为36.40%，归一化空间分布重叠16.24%。Robotaxi/HV落在共享网格的订单比例分别96.09%/34.34%。Robotaxi 单独正值的网格小时从75,064降为35,541：全表中39,523个这样的单元位于HV全零的尾部10天。

因此，空间分布不一致的描述对这次日期截取较稳定，但“独占活动”的时空计数受到不等窗口显著影响。21日对照仍然不是实际同日或共同服务区的因果比较。

### 不混用 Figure 2c 的指标

发布的 Top-30% overlap：早高峰34.50%、白天44.26%、晚高峰38.89%、夜间40.54%、全时段45.72%。作者定义是两类 top-k 网格交集除以 k，**不是 Jaccard**。排序并列与单模式零计数也会影响 top-k；k 扩展到全并集时重叠趋于100%具有定义上的机械成分。

fig2c 按两类各自最早的共同数量日期聚合，不等于取真实日历交集；不能直接用 fig2b 全31日重算后声称复现同一估计量。CCI 雷达值保留于 JSON，仅作为已发布描述，不用来推断能力阈值。

## 4. Figure 4：暴露差异，而非能力识别

发布样本为 HV 3,555,128 单、Robotaxi 408,236 单，不同于 Figure 2 的样本量。发布距离加权 OPCI 均值分别为2.65和2.20，差值−0.45。作者代码使用 trip `SNE_mean`，以 `dist_km` 加权，图轴更名为 OPCI；不是订单比例权重。

用发布的四舍五入分箱宽度×密度重构，积分为1.0007/1.0006；重归一化后的分箱中心均值约2.6452/2.1958，与发布均值一致到其精度。两种距离加权直方图的重叠约39.45%，仅为舍入后的分箱近似，不是行程/道路集合交集。源表 Welch p 存成0，不解释为概率严格为0；没有重做显著性检验。代码中的 Welch/Cohen's d 与距离加权均值也不是同一加权口径。

Figure 4b 有15个 CCI 分箱，观测合计408,196；附注明确另有40单在边界外排除。CTX 与 POP+SNE 的预测合计分别428,457.25和392,947.73，并不满足总量守恒，这些是拟合预测而不是订单重新分配。作者图4b代码在同一聚合分箱上拟合和展示；仅凭这一图不能宣称样本外或调度收益。补充材料另有验证产品，未纳入本轮。

公开直方图没有与 Figure 2 联接的逐订单、网格、日期键，因而目前不能做共同服务区内的复杂度标准化、同 OD 对比，或分解“区域选择”和“区域内路线选择”。

## 5. 对本项目的下一步价值

本轮没有得到新增硬门或直接校准西安 profile 的依据。得到的是三个需要分别识别的对象：

- **活动域**：哪些地区有已实现订单，受需求、供给、区域规则和窗口共同影响。
- **条件暴露**：在已完成订单中，经历了什么道路复杂度；受选择影响。
- **可服务性**：对给定请求与车辆，是否具有可行候选；需要兼容图与时间证据。

现阶段最划算的后续工作是先清点我们现有 timing×gate 固定状态结果，明确已有证据及真正缺口，不再重复已完成实验。若以后做共同区域比较，首先需要原始观测日期、真实服务区/在线车时，以及可连接的 OD/路径暴露数据；无法取得时应保留不可识别结论。另一条独立路线是只读检查 driver-chain 周转与接续机会，不能把本图的空间相关性直接作为调度策略。
