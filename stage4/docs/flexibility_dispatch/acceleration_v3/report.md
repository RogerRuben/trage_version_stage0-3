## 实际修改

1. `flexibility_v3.py` 按完整当前/未来约束耦合图分解；固定 idle 状态不跨情景
   形成虚假的耦合；没有当前选择的纯未来部分用稀疏最大匹配求常数项。
2. 固定状态在生成约束时直接代入；一次生成稀疏矩阵，词典序阶段只追加少量锁行。
   不再建立完整矩阵后转回 Python 字典逐行重建。保留有用的隐含车辆容量约束。
3. `routing_v3.py` 用一个轻量 shadow LRU 模拟旧有缓存填充顺序，然后只提交
   真正需要的查询。不会复制整份 50,000 项 LRU。舍入键冲突和失败重求仍保持
   原查询语义；默认仍是独立 1×1。
4. `route_bank_v3.py` 用有界后台写入、无 recency 更新/索引的原始缓存表。
   内存队列最多两批，单批最多 4,096 条。队列满只放弃可选缓存写入，不丢结果、
   不丢候选；512 MiB 主库上限加小 WAL/事务开销。不存在 order×vehicle 稠密表。
5. `routing_v3_workers.py` 增加最多 32 targets 的单源前向候选后端。失败 cell
   回到原 1×1。它在本次有限查询集上通过对照，但仍可切换、配置默认关闭；
   不把有限一致性推广为任意路网/日期都等价。

现有 v1/v2 配置未改；v3 使用新目录和可切换配置。不改变 Top-K20、30秒 rolling、
300秒 patience、3个 Train 情景、600秒 horizon、10秒总求解预算或质量逻辑。
未做 Benders 大改，未使用商业求解器，未重训 M3，未启动全天 v3。
