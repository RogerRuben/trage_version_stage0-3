## 1. 研究问题与模型关系

主问题保持为：**在相同预定供给与服务规则下，初期能力受限的 C 车队，如何通过上线布局、任务分配与可续服务安排，改善资源的有效使用和空驶效率，同时保留混合系统服务水平？** M/A 与规模是后续边界分析，不扩成平行主线。

本文件延续[原布局—服务链模型](../model_and_structure_v1.md)，不是另建一个与派单器竞争的“运营模型”。上层选上线位置，下层决定当前接单、等待与移动；两层共享能力、时空状态、需求和资源约束。本文更新的是当前等待语义、输入角色以及数学目标与加速实现的边界，**不修改旧稿和旧实验**。

保留方案 A：同班次、同标签、同预定车时、同候选上线点、同请求分母。不自动开放原方案 B 的驻点数、围栏面积、网络开通费或采购车数。

### 1.1 原目标与当前实现不是同一层的保证

原总问题为非预知策略下的词典序目标：

\[
\operatorname{lexmax}_{s,\pi\in\Pi^{NA}}
\left(\mathbb E[Y(s,\pi)],-\mathbb E[L^{empty}(s,\pi)]\right).
\tag{1}
\]

先考虑服务量，再考虑空驶，不以任意风险权重合成一个安全评分。没有可靠运营单价时，报告空驶距离和时间，不宣称利润最优。

当前加速执行器不是式（1）的精确全天解：它精确选择已准入的稀疏当前动作，用有限历史情景的粗粒度价值近似未来。`SERVICE_PRESERVING` 优先级实际是临界服务、当前服务、carry-over 服务、近似续行价值；`CHAIN_DEFER` 将续行价值提前。全局次级总空驶优化已移除，只保留同等主值动作的局部短距离偏好。见[当前流执行器](../../../dispatch/scheme_a_current_flow.py)。

因此，后续若恢复真正的空驶次级优化，是在原框架内补齐目标；若改为“成本最小、服务不低于某下限”，则是明确的目标修改，需作者另行确认，不能根据本次最佳服务率事后定一个有利下限。

## 2. 资源、时间与信息

资源 \(v\) 是有效服务班次，不是已识别的采购车辆；带类型 \(k(v)\in\{C,HV\}\)、上线 \(a_v\)、停止接新单 \(b_v\) 和上线位置。状态为

\[
\sigma_v(t)=(k(v),z_v(t),t,a_v,b_v,\ell_v(t),c_v(t)),
\tag{2}
\]

\(\ell_v\) 保留上一条有向路段、路线接口与移动进度；\(c_v\) 是已承诺任务。不能把同一区域里的车辆都看成具有相同后继动作。

上车时间继续作为请求释放时间 \(r_o\)，这是作者接受的研究近似，不再重新打开请求提前量问题。当前 v4 的合法承诺条件为

\[
r_o\le t<r_o+300,\quad a_v\le t<b_v,
\qquad 0\le\widehat p_{vo}(t)\le600.
\tag{3}
\]

300 秒限制接单，600 秒是独立接驾上限。接单后不取消，不重置耐心，不额外施加 300 秒到达上限。预测完成时间为

\[
\widehat f_{vo}=t+\widehat p_{vo}(t)+\widehat T_o+T^{overhead}.
\tag{4}
\]

当前额外上车停留为零；以后改变需另行声明。\(\widehat f\) 可超过 \(b_v\)，但任务结束后不能继续接单。已承诺行程通过物理排空完成，行政运行时限不是下班时刻。

决策只能使用 \(\mathcal I_t\)：已释放请求、车辆现状、既有模型预测与历史参考。未来场景使用已有 20161010/17/24 模板；共同空车调位参考使用 20161009–24 的历史起点分布。不是提前读取 Test31 后续真实订单。实际载客时长仅承诺后交给执行器，不能反过来选车。

## 3. 单一稀疏动作模型

### 3.1 布局与当前动作

\(s_{vz}\in\{0,1\}\) 选择上线点，\(\sum_zs_{vz}=1\)。每轮对可用车辆选择：

- \(x_{vo}=1\)：承诺服务已释放订单；
- \(w_v=1\)：保持当前等待状态；若车辆在可中断调位中，保持其已发出移动，不瞬移；
- \(m_{vz}=1\)：发出合法空车移动。

\[
\sum_o x_{vo}+w_v+\sum_z m_{vz}=1,
\qquad \sum_vx_{vo}\le1.
\tag{5}
\]

忙碌或尚未上线资源不作为当前可执行车辆。所有类型共享订单唯一性；不能分别求 C、HV 的服务能力后相加。移动受原次数、接驾/移动时间、班次与方向衔接约束限制。

式（5）表达统一模型的动作域，不声称 v4 全部动作都已联合优化：v4 的实际移动由共同历史需求缺额规则执行，价值选择的 MOVE 未启用；三组结果不能当作“类型条件调位价值”已经验证。

### 3.2 可行弧与路线选择边界

只在稀疏候选集合 \(E_t\) 中保留

\[
A_{vo}(\mathcal I_t)=
A^{common}_{vo}
A^{time}_{vo}
A^{loaded}_{o,k(v)}
A^{pickup}_{vo,k(v)}
A^{join}_{vo,k(v)}
A^{accept}_{o,k(v)}=1
\tag{6}
\]

的组合。各因子分别表示共同输入、时间、载客路线、接驾路线、方向衔接和乘客接受。HV 不受 AV 接受限制，但保留共同订单支持与时间要求。

当前载客路线是事前给定的历史路线代理，\(A^{loaded}\) 使用该请求已有的冻结预测，不在每个 epoch 重跑 M3。接驾/空车路线先由 Valhalla `auto` 生成，再作 C 动作及接口检查，**不是主动搜索 C 最优路线**。通用路线被拒绝，不证明该 OD 没有另一条 C 可行路线。

研究 C 规则为信号控制左转、禁止环岛/掉头与既有交通环境外暴露预算；直行/右转不自动要求信号灯。它是假设性运营能力，不是实际商业车辆安全认证。

如以后需要少量候选路线，可将 \(x_{vo}\) 扩为 \(x_{vor}\)；单路线是其特殊情形。但新路线的预测与执行时长必须有独立合法来源，不能复制原历史路线时长。本轮不生成候选路线、不改变 C 规则。

## 5. 类型条件的可续服务价值

对当前合法动作 \(a\)，用预测完成/到达状态定义

\[
\Delta\widehat V_v(a)=
\widehat V_{k(v)}(\widehat\sigma_v^+(a),\mathcal I_t)
-\widehat V_{k(v)}(\widehat\sigma_v^+(WAIT),\mathcal I_t).
\tag{7}
\]

WAIT 基准保留已发出移动与真实当前位置，不视为回到旧起点。\(\widehat V\) 应来自历史兼容需求、预测完成时间、有限接续连接以及两类车辆对同一需求的竞争，而不是区域总订单量。

对 C，热门但后续不兼容的落点不自动有高价值；对 HV，不能只按 C 能做的订单估计后续机会。当前通用历史缺额移动按**总历史需求**分配目标，能力只用于拒绝不兼容移动，未按 C 兼容需求主动选择目的地。这是明确输入缺口，不是通过修改 profile 可解决的事项。

高服务率下，任务多由 HV 兜底；研究价值应同时看 C 资源转换、接驾、空驶与区域/小时差异。不是强制 AV-first，也不惩罚一切等待。低需求时保留车辆等待，可能比无效移动更合理。

现有价格/续行价值是有限规划域的近似信号，不能叫真实新增服务量或完整问题最优对偶证书。v4 每组 289 次刷新仅 5/9/11 次全部情景价格闭合；不继续堆深度来追求包装上的“全局最优”。

## 6. 空闲与周转的报告口径

以每个班次 \([a_v,b_v)\) 与当地日历日 \([0,86400)\) 的交集为分母。按记录活动的实际区间计算

\[
H_k^{admission,day}=
H_k^{pickup}+H_k^{loaded}+H_k^{move}+H_k^{unoccupied}.
\tag{8}
\]

只有区间补集才称本模型的未执行任务/调位空闲。承诺后跨 \(b_v\) 的工作、午夜后工作另列；不能用完整任务忙时除以更短班次分母。这里没有充电/维护模块，资源也不是实际商业在线车队，不能直接校准武汉图3的 Idle。

订单小时按请求释放分组；车辆小时按实际活动区间积分。两张表不是同一时间归属：当小时载客可能服务前一小时释放订单。

## 7. 由本次诊断限定的最小后续修改

详细结果见[已有结果诊断](diagnostic_report.md)。当前最小实施清单按先后为：

1. **补齐连接辨识的轻量计数。** 每请求增加 C/HV 最终合法候选计数及“存在合法 C 但选择 HV”的计数即可；不保存全弧、全车辆快照或大矩阵。并明确接驾段、上一任务出发衔接、接驾—载客衔接的掉头/拒绝来源，避免把接口证据缺口当普遍能力缺失。下一实现批次再落地，本轮不改运行代码。
2. **将移动目标从总需求补位升级为类型条件机会。** 只用历史期已有产物，考虑 C 合格需求及合法空车连接；保持共同资源、移动次数、时间和能力规则。先识别现有通用路线筛选是否错过可行连接，不直接开启全路网重规划。
3. **在同一稀疏当前动作模型内实现实际声明的空驶次级目标。** 保持服务/临界保护与物理约束；先保证目标、求解器与报告一致，不引入未经标定的利润、风险权重或 AV 份额奖励。

不同时增加充电、拼车、采购、围栏、M/A 多主策略或耐心参数扫描。现有允许暂缓没有明显总服务优势，暂不作为主策略扩展方向。

本批交付只到模型、输入映射和已有数据诊断。**没有新增放行 Gate，也不自动开始上述运行修改或新的全天实验。** 下一批只围绕以上最小修改实现，仍使用当前 300/600 秒规则和冻结上游；实验条件另行固定后再运行。

## 8. 科学边界

- 97.5% 是一日、一种子、高质量共同订单回放结果，不是商业市场真实成功率。
- C 低利用不是自动证明 profile 错误；附近有 C 也不是最终合法候选证明。
- 原路线被拒绝不是 OD 不可达证明；通用路由器的选择与 C 限制的影响需要分开。
- E/Q/C 与经验 caps 是运营适配描述，不是安全认证；所有旧特征不需要重复门控。
- 武汉公开[图3](https://www.nature.com/articles/s41893-026-01944-2/figures/3?error=cookies_not_supported)支持大量 Idle 活动时间的描述，但源表示例以未被订单活动覆盖的时段作为残余，不能等同于在线可派的等单时间。本文不使用其比例调整西安参数。
