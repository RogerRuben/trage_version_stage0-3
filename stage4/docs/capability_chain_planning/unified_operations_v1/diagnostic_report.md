## 1. 结论

总体服务率高，但 C 的未占用班次时间非常多，而且并非仅发生在低需求时段。当前影响 C 利用的候选瓶颈包含接驾路线、掉头/路口限制、方向衔接及目的地选择；不能仅用“布局不够好”或“C需求不足”解释，也不能直接认定存在代码错误。

第二组中，C 合格且接受 AV 的 6,534 单，985 单由 C 服务、5,433 单由 HV 服务、116 单过期。后者中 5,011 单在请求生命周期内曾有附近可用 C 资源，只有422单未观察到。这是深入分析连接与分配的依据，**不是 5,011 单都能无代价改派 C 的证明**。

后续应先把 C 接驾/衔接的可行性证据、类型条件的移动目的地和真实空驶次级目标接到同一个模型，不再先加更复杂暂缓。旧全天结果和条件全部保留。

## 6. 与武汉空闲现象的关系

武汉[公开图3](https://www.nature.com/articles/s41893-026-01944-2/figures/3?error=cookies_not_supported)区分乘客、充电、调度和Idle；源表各小时Idle超过50%。但作者[公开示例](https://github.com/Tlab-seu-code/Urban_Robotaxi_Analysis-/blob/d8de2c56e6c127542c98c9d224021cd131cd4f77/6-figure/fig3c.py)以订单未覆盖区间作为默认Idle，没有完整在线日志，并以呼单至完成构造乘客订单活动。

本模型空闲则是已声明准入窗口内的物理事件补集；无充电维护，采用有效服务班次。两个分母与状态定义不同，不能把武汉比例校准成西安目标，也不能把本轮84.79%叫作复现真实AV等单比例。

可借鉴的是将高服务、高空闲与空驶效率分开研究，而不是为了逼AV满负荷强制移动、放宽能力或引入拼车/能源模块。

## 7. 最小结论与后续范围

1. 保留当前高服务基线；旧暂缓没有明显总体优势，不再优先加深前瞻。
2. 在同一个模型内，先明确C接驾/衔接候选究竟在哪一环节被拒绝，以及合法C和HV如何竞争。
3. 共同历史补位目前按总需求选目的地，不按C兼容需求选目的地。优先把已有Stage2–3的类型、时间和连接信息用于这个决策，而不是再加重复硬门。
4. 恢复真实声明的空驶次级目标；不把局部稳定排序称全局成本最优。

本批只完成诊断与模型说明。没有修改运行策略、300/600秒、C规则、q10、P70、冻结M3、输入/布局或旧报告，没有启动新全天。

## 8. 解释风险与复现边界

ARS 11类解释风险均检查：整体与小时/区域分开（Simpson）；有效班次不推真实车辆在线（生态）；明确高质量共同样本选择（Berkson）；成功服务与合格子集的条件统计不作总体效应（collider、幸存者）；完整订单和车时分母（基础率）；不将旧低服务后新结果当随机重复改善（回归均值）；完整三组与全部支持区域留存，不挑p值（多重搜寻）；固定聚合口径、无调参（分析路径）；拒绝见证不当因果分解（相关/因果）；执行真值只用于事后时间核算，不送当前策略（反向因果/信息时序）。覆盖11/11不等于风险全部消失。

原实验没有重复运行：无置信区间、无总体显著性、无预测决策优越性或全局最优性结论。诊断脚本可从既有完整产品重新生成聚合JSON；它不验证商业C能力，不能从记录缺失证明没有更好的候选。
