# 基础成本优化（2026-10-15）

本轮只处理静态证据整理、当前接驾校验和调位路径复用。不改变 V3 联合目标、首改善规则、邻域预算、候选 Top-K、能力/乘客规则、300 秒接单、600 秒接驾、30 秒派单或 300 秒预测更新。没有训练、GPU、稠密矩阵或全天实验。

## 改动

1. 对冻结路网的 289,295 条边界记录、419,907 条转向记录和 43,685 条控制记录建立紧凑索引。使用 Arrow 字典键、排序的 64 位摘要和整数行号；摘要碰撞仍核对原始完整键。保留源行顺序、重复边界成员及缺失键语义，不为每条边建立一套 Python 对象。
2. 全表字符串分块只合并一次，避免 Arrow 每次取少量行时重新拼接全列。索引查询使用 uint64 批量查询，避免 Python 大整数引起整份索引的隐式类型转换。
3. 当前空驶路径的交叉口分类与静态表切片复用已有有界缓存。同一路径的完整方向序列参与键，不截断 INTERNAL 路段，不把反向身份投影成正向。
4. 衔接结果缓存同时绑定完整 typed 序列、reverse overlay、实际上下车位置、道路吸附端点、容差与诊断模式。只有完全相同的静态接口才能复用。请求是否已出现、当前 ETA 修正及期限仍每次检查。
5. 接驾与调位使用同一个 Actor、同一几何快照时，共享原有 1024 条 OD 路径缓存。需要执行几何的调位也可复用已核实证据；如果路径已经被驱逐，则重新获取并校验，不能凭证据捏造路线。失败结果保持原字段与原因。
6. 历史衔接解析只取所需的方向支持与 encounter 差分，不再分类随后会被丢弃的整条前车/空驶/后车路线；真正新增的跨段 movement 仍完整分类。没有 reverse overlay 时不再创建无用的逐边分组。
7. 稀疏 ETA 批次共用目标位置、分钟键与 beta 的格式化结果；保留精确 OD 键、旧的四舍五入别名先后顺序和接驾排除规则。

缓存上限未扩大：静态结果 16 MiB、连接证据 32 MiB、几何行组 64 MiB。新增索引预算 32 MiB，实际约 16.82 MiB。原 1536 MiB 进程门槛不变。
