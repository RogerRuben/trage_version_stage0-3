## 4. 新结构：真正分离粗规划和快执行

旧实现所谓300秒粗层只刷新历史任务库，30分钟全链问题仍每30秒重建。这不是真正的两层算法。

现在选定：

```text
已有历史订单 + 冻结M3 + C/HV能力适配
                  ↓ 每300秒粗层
         竞争调整的续行价值表
                  ↓ 每30秒查表
当前合法SERVE / WAIT / MOVE → 稀疏当前动作流 → 原生执行
```

### 4.1 粗层：竞争调整的续行价值，不是每车各自“都能再做3单”

继续使用原历史日期、M3 P50、30分钟视野及既有能力／接受设定。车型、区域、预测可再次接单时刻和停止接单窗口组成粗状态。位置与时间聚合只用于估值，**不是车辆瞬移或实际道路认证**。

建议粗层使用有限历史服务链的线性松弛，按粗状态供给和历史任务的共享容量估价：

\[
\max_{y\ge0}\sum_\omega p_\omega\sum_{s,p\in\mathcal P_s^\omega}|O(p)|y_{sp}^\omega,
\quad \sum_p y_{sp}^\omega\le n_s(t),
\quad \sum_{s,p:o\in O(p)}y_{sp}^\omega\le1.
\]

供给仅来自当时可用信息、已知班次及冻结预测。每次更新一次小型稀疏LP，不为每个当前真实选项复制未来整数链，不规划独立未来MOVE。已有原始客户路径和历史稀疏接续证据可复用；固定道路body／必要连接按候选稀疏预处理，**不做订单×订单×时间稠密张量**。

历史任务价格\(\alpha_o^\omega\)可用于粗状态机会价值：

\[
\widehat V(s)=\sum_\omega p_\omega\max\{0,\max_{p\in\mathcal P_s^\omega}
(|O(p)|-\sum_{o\in O(p)}\alpha_o^\omega)\}.
\]

这比各车独立取最大链长更合理：多人竞争同一批预测订单时，不能人人都宣称还可以做3单。查询用的零供给状态也需要已定义候选；不能因为LP没建立该状态就把缺失值假填为零。若粗层真的不可用，明确启用当前服务优先模式并记录原因，不给实际路线新增UNKNOWN拒绝。

这里是**受限预测域的价值近似**，不是全城全链上界、整数边际服务量或真实未来容量。位置／窗口聚合、列截断和价格量化必须在实现后报告；不把原小例子对偶证书直接搬来作城市证明。

粗层实现及表接口**尚未完成**；上式是本次选定的接入规格，不能将已完成的快层计时当作它的速度。

### 4.2 快层：当前动作图，只有物理可执行动作

当前道路、方向、交叉口／左转、车型能力、乘客接受、300秒耐心、班次退出和承诺继续完成都由既有接口检查。BUSY和未上线资源不参与当前动作选择；它们只影响粗层未来供给。共同请求分母与车辆车时不改变。

每个可用车辆有一个WAIT。SERVE经请求节点（容量1），MOVE经共享池节点（容量50），WAIT直接到汇点：

\[
\sum_{a:v(a)=v}x_a=1,\qquad
\sum_{a:r(a)=o}x_a\le1,\qquad
\sum_{a:\mathrm{MOVE}}x_a\le50.
\]

这些当前约束可以用整数容量的稀疏单商品流表达；不声称原多服务、多类型链问题也具有这种性质。所有MOVE目的地没有额外站点容量时，可只保留每车主要价值最高、同值距离较短的MOVE，这是当前模型中的精确支配删除。

适用范围是当前方案A协议：`city_joint_validation.native_configuration`明确将三项全局Gamma暴露预算设为None、关闭额外成本层。**该当前流不是所有Stage4策略的通用替代品**；如果重新启用全局平均暴露约束或其他耦合行，必须明确处理，不能省略这些行仍声称是同一网络流模型。

当前服务收益\(r_a\in\{0,1\}\)，未来机会增量
\(\Delta V_a=\widehat V(s_a)-\widehat V(s_{WAIT})\)。采用同一单位的
\(R_a=r_a+\Delta V_a\)，不是任意风险加权平均。粗价值量化到1/3个服务机会，范围0—3；当前内核的差值整数输入范围-9—9，不让浮点大权重损害主要优先级。

- 保护当前服务：临界 → 当前服务数 → 当前延期服务数 → 当前加续行价值。
- 联合控制：临界 → 当前加续行价值 → 当前服务数 → 当前延期服务数。

主要优先级用严格整型支配编码实现：每层单位权重超过所有后层可能总变幅。不是0.3/0.7风险分数，也不含epsilon目标锁。只有当前模型及给定近似价值的主要目标最优；空驶采用稳定局部择优和实际统计，**不再为最后一米做全局最优证明**。

新核位于 `stage4/dispatch/scheme_a_current_flow.py`。默认优先使用隔离的OR-Tools CPU整数流；编译型成本范围不安全或依赖缺失时，使用任意精度整数参考流，不把整型成本强转成不安全浮点。[OR-Tools最小费用流接口](https://developers.google.com/optimization/flow/mincostflow)

参考流支持周期性墙钟检查；超时返回已验证合法选择或明确的服务优先备份，不伪称OPTIMAL。C++接口不能中断正在执行的调用，因此入口检查预算、出口明确记录WALL_OVERRUN，不宣称具有绝对端到端硬时限。输入错误／重复订单／物理资格不一致仍应停止，不能靠“降级”隐藏数据错误。

### 4.3 保留与牺牲

| 保留 | 取消／近似 |
|---|---|
| C受限能力下的上线布局、相同车时与共同订单 | 每30秒的全资源×选项×三情景链搜索 |
| HV灵活性、M3对再次可用时间和周转的作用 | 精确未来客户竞争转为粗层LP价格与状态聚合 |
| 真实C道路／动作与当前客户时间可行性 | 不把粗状态作为真实有向来向或道路证书 |
| 普通订单可延后、实际全天多单周转 | 不执行未来链，不要求未来整数链全最优 |
| 当前空车移动和50次共享配额 | 独立未来MOVE变量及次级距离全局最优证明 |

这是**算法语义改变**，不是声称与旧重算法完全等价的工程优化。新旧结果必须用不同版本／目录；不与旧partial拼接。47批旧布局可以作为有明确来源的固定布局对照复用，不能改称新粗LP的最优布局。
