## 1. 这次改了什么

V1每30秒重新建立整队未来问题，丢掉上一轮已经找到的可行计划，再重复搜索相似链、求解相似小邻域。V2保留共同计划的结构，以变化驱动修补和局部搜索。

| 问题 | V2处理 |
|---|---|
| 上一轮计划被丢弃 | 保留每个情景/车辆的未来订单顺序，下轮从新根状态重新验证与计时 |
| 同一300秒预测快照反复建图 | 跨轮复用一个历史预测快照的空间索引和惰性后继候选；新快照/pace变化即失效 |
| 每轮扫描并优化所有旧需求 | 活动前沿来自新请求、新预测、失效占用、改变的资源域及未完成搜索；真实待单每轮都保留 |
| 指定目标仍广泛枚举所有路径 | 在原稀疏后继域上做至多三单的反向可达裁剪，不搜索不可能包含目标的分支 |
| 同一邻域反复求解 | 当前整队计划和该组列池均未变时，跳过重复访问；任何计划变更都保守失效 |
| 恒为零的目标还调用求解器 | 零目标阶段直接获得常数最优值，仍保留原词典序，不改成加权目标 |
| 先生成很多根才开始闭合 | 根候选与替代扩展交替产生，尽早闭合/评价；不以单车或部分组合不改善为拒绝理由 |
| 标签预算到达时丢掉已有列 | 停止生成新列，在剩余共同时间内评价已有合法列；不额外增加标签或求解时间 |
| 固定忙车未来重排消耗控制搜索 | 纯固定当前根的组不做决策MILP，但可行续行及占用继续保留，也允许通过中性扩展进入可改变当前动作的联合组 |

布局不重做。本轮升级针对在线滚动执行；保留V1已经生成的三种位置方案。不能把这些布局说成已经由V2重新优化。

## 2. 增量复用不等于照搬旧计划

每一轮仍从最新合法当前动作域选一份现实动作，所有情景共同使用这份选择。不会再次执行上一轮的SERVE或MOVE。

未来计划只携带订单身份和顺序：

1. 已不存在、已被当前动作消费或过期的订单不能继续占用。
2. 从当前新的预测根重新计算接单、接驾、服务完成和空驶距离；不沿用旧的旅行时间或假设已经完成的预测行程。
3. 去掉失效节点后，新的相邻关系必须仍属于当前稀疏后继域；否则不能直接连起来。
4. 先恢复仍合法的已有拥有者，再用有限初始化预算填补新资源/损坏续行；共享请求容量始终检查。
5. 背景忙车和未上线资源仍是固定当前前缀，不变成可执行的当前接单车。其未来占用不被删除，只是不每轮重新全局优化。

预测快照切换时，旧负ID失效；仍存在的真实待单也须按原期限重验。内存不携带旧物理状态、旧最优性证书或全日DataFrame。

## 3. 哪些保持，哪些改变

保持：

- C/HV能力口径和原物理接驾/移动验证；Stage1–3产物不重算。
- 300秒内接单、独立600秒接驾上限，真实待单期限不重置。
- 三个既有历史M3情景、30秒滚动、300秒更新、1800秒规划、最多三单。
- 一份共同当前动作、各情景共享订单容量、外部资源占用扣除、紧迫订单保护及原词典序目标。
- 最多6资源、128个部分状态、50,000次深搜索标签，20,000变量/150,000非零元，以及原10秒共同决策预算和1536 MiB进程门槛。

历史图/完整查询复用、反向不可达裁剪和零目标跳过不放宽原链域或数学约束。但活动前沿、增量初始见证、固定根组跳过、重复状态抑制和延迟列生成会改变有限预算下的搜索顺序及列池。因此这是**新的执行策略版本，不是城市结果已证明完全等价的提速**。

重复邻域只在当前整队计划对象未变且本组列版本未变时跳过；不把未证明的历史访问称为最优证书。任何当前根/拥有者变化均使这些访问状态失效，缓存不跨决策轮次。

## 4. 内存和计时

- 只保留一份选定未来计划、一个预测快照及活动前沿；不累积历史列池。
- 静态后继候选缓存最多20,000个引用、2048项；反向前驱与可达缓存各最多128项/20,000个引用。
- 轮内查询复用最多512项，重复邻域最多128项。邻域键只保留小车群的版本信息，不存全城约束矩阵副本。
- KD-tree和索引规模随当前任务/动作数线性增长；不构造车辆×订单×时间稠密数组，不启GPU或多组并行。
- 所有缓存计入同一原生进程内存；不领取额外RAM或求解时限。

新增可直接汇总的分段计时：供给状态、预测索引、计划修补、前沿、搜索和计划保留。搜索内部再记录列查询、整数模型构建、真实求解器调用时间及其他开销；嵌套计时有明确标识，不能重复相加。

求解器调用计数和计时在调用中断时也保留。另记录“相对本轮初始见证，最终当前动作是否改变”“只改善未来计划的接受次数”、图/查询复用、重复邻域跳过和标签预算刷新次数。旧分支没有测量的字段不填成0。内部待处理订单ID只留在内存，不进入这些公共诊断摘要。
