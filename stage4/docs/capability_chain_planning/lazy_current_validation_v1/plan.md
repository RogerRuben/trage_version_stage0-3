# 固定子图上的按需路线精查：执行前计划

## Material Passport

- 阶段：独立算法原型与一次固定小对照；授权来自用户“完成下一轮任务”。
- 日期：2026-10-14；状态：执行前计划，尚无正式结果。

- 边界：不运行全天仿真，不训练或重新推断 M3，不改变已冻结的城市控制器；仅使用 CPU 单进程和稀疏候选。

## 要回答的问题

昂贵的 C 接驾路线及拼接检查，能否只查那些可能改善决策的候选，同时保住完整目标，而非仅保住服务数量？全量精查 EAGER 保留为独立接口默认值；LAZY_CERTIFIED 是显式可切换的研究选项，尚未接入城市控制器。

## 方法和保证范围

在固定已生成的 SERVE/WAIT 子图上，先求已通过检查的可执行下界，再给未检查 C 候选赋予乐观界，求上界。若上、下界完整目标相等，则无需继续查询；否则只检查上界解选中的未查候选，更新后重复。

完整词典序目标为：紧迫订单数、当前服务数、延续等待订单数、当前服务与后继价值的既有整数目标、负空驶距离。距离仅在目标比较中按既有 1 mm 精度取整，实际物理距离不改动。这里没有 RELOCATE 动作，也没有声称它等价于全天原控制器的全部决策。

对未知候选，接驾距离下界固定为 0；后继价值上界在同一冻结价格快照上，以零接驾时间计算。更晚就绪不能增加既有后继路径集合，因此真实后继整数值不得超过该界。实际值每次查询后会检查；违界则拒绝证书，不静默修正或放宽。

设真实可执行图为 G，乐观图为 G+。固定图中 G ⊆ G+，且每条未知边的乐观目标不小于真实目标。已检查可行解给出下界 L；只有求解器证明主目标和距离次目标最优时，其乐观解才给出上界 U。若 L = U，即获得该固定图的完整词典序最优值。不同等价最优分配可以有不同车辆身份；不要求逐条选择完全相同。该结论不保证后续轨迹、全天服务或未来真实需求最优。

未解析、资源超限或查询预算用尽不能当作路线不兼容。只执行已检查动作。超出时间时保留已检查可行解并明确标为未获得预算内完整证书。

## 一次对照的固定范围

- 时刻：07:30、08:30、17:00、18:00，固定四个；不按结果筛选。
- 车辆：由上线、已开始服务、已完成服务和已开始移动的事件前缀，恢复该时刻已知位置、未占用、未在途的车辆。不猜测在途位置。
- 请求：已释放、已进入原控制器等待集、尚未接单、仍在 300 s 接单期限内；按 seed=20261014 稳定哈希排序，最多 24 单。
- 候选：保留现有半径、Top-K=20、乘客接受与 C 订单兼容规则，先统一计算矩阵接驾时间；600 s 接驾 ETA 上限不变。
- 旧产物没有逐轮完整候选图，因此这是已知停车车辆的 as-of 子图，不是原全天实验的精确快照，也不是完整混合车队容量测量。
- 两种方法共享同一个子图和后继价格；全量精查给出所有未知 C 边的结果，按需精查只查询必要边。逐个核对按需查询结果与全量结果，检查查询顺序是否改变接口结果。
- 两种方法每图交替先后次序：E/L、L/E、E/L、L/E。清空路线与空闲方向的 Python 缓存；静态证据和 Valhalla 内部缓存不作伪冷启动，计时仅是这一次原型观测。

## 资源和计时

- 每种方法每图：10 s，共享检查与求解时间；底层原接口的路由单批预算仍独立，若不可中断调用晚返回，明确记录 wall_overrun，不能报预算内成功。
- 整组：600 s；进程峰值上限 768 MiB；启动至少 1536 MiB 可用内存；运行至少保留 512 MiB；路由 worker=1；不用 GPU，不生成全车辆×订单大矩阵。
- 单列共同准备/矩阵查询、精查候选数、实际 scalar route/edge walk 次数、空闲方向恢复、求解与精查耗时；不把减少查询直接换算成全天提速。
- 一次正式运行，保存失败或超限现场。代码逻辑故障不自动重跑、不换时刻、不扩大请求数寻求正结果。
