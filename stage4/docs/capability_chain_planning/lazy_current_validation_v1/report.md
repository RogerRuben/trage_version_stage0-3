## 1. 人话结论

新方法不是“先随便挑几条路、漏掉的算了”，而是先问：**即使把没查过的候选都按最乐观情况考虑，能不能比当前已检查方案更好？** 若不能，就不必查；若能，只查乐观解用到的候选，再重新判断。

这次完整目标在四个子图中全部与全量精查相同，并获得预算内证明；但效率不一致。17:00 可以不查两条 C 候选，08:30 则需要查完七条，分成五批还增加了求解开销。

因此，本轮支持“正确地跳过部分精查”的机制和独立接口实现，**不支持把它默认替换城市控制器，也不支持宣称全天明显提速或新增服务提升**。

## 2. 比较对象没有偷换

两种方法共享时刻、车辆、请求、候选和后继价格：

- EAGER：一次批量检查全部未知 C 候选，再优化。
- LAZY_CERTIFIED：按乐观解分批检查，直到完整目标的上、下界相等。

比较完整词典序目标：紧迫订单数 → 当前服务数 → 延续等待订单数 → 当前服务和后继价值的既有整数目标 → 总空驶距离。距离的目标精度为 1 mm；并未修改物理路线、距离或时间。

四项必要测试覆盖非竞争候选跳过、候选被拒及真实后继值变化、无效乐观界/未解析答复拒绝、完整优先级一致；4 passed in 1.47 s。指定新文件 compileall 和 Git diff check 通过。最初只读准备检查发现订单基础表包含 C/M/A 三份记录，已确认同订单坐标一致，并明确读 C 分区；这是正式执行前的数据粒度修正，没有重跑正式对照。

完整保证来自固定图关系，不是服务数量巧合：真实图是乐观图的子图，每条未知边具有有效目标上界；只有主目标与距离次目标都已证明最优的乐观解才能当上界。已检查解为下界，两者完整向量相等即闭合。不同等价最优车辆分配不必逐条同名。未来真实服务数和全天最优性不在保证内。
