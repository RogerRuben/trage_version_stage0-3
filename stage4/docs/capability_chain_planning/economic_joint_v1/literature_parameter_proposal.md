# 经济参数的文献依据与情景草案

日期：2026-10-16。对应上一版[经济异质性与联合规划方案](design_and_workplan.md)。

2026-10-17更新：本文件保留文献提取与换算记录；当前实现以[完整派单机制与模型](dispatch_mechanism_and_model.md)为准。已核对Chen/Gao期刊正式版：25%也对应Gao正式版§9.1案例设定。用户已确认统一研究车费为8元＋2元/载客公里。固定支出和未单独建模的清洁/远程协助不再列为实现前置缺口；新主模型只含统一车费、HV结算与AV变动公里成本，原下表不作为运行配置。

## 1. 本轮结论

不能继续把旧模拟器里的金额常数当作校准值。建议采用**文献锚定、统一计价、分项核算的研究情景**，而不是给AV添加使用奖励或任意指定“AV成本是HV的若干倍”。

本轮已经核对原文及关键表格，并形成[参数草案](../../../config/economic_literature_parameters_v1.json)。它不是运行配置：车费及若干成本尚未定值，现有控制器不读取它，没有改派单逻辑、没有新实验。文献数值可以支撑情景设计，不能证明西安2016真实利润。

## 2. 哪些文献分别解决什么问题

### 2.1 现金流结构，而非直接抄一组金额

Gao、Wu、Dimakis、Courcoubetis的混合车队研究区分了平台自营AV与司机自有车辆：平台获得AV订单车费并承担其行驶成本；HV订单则向平台支付佣金，车辆成本由司机承担。作者稿第8页及脚注4给出20%—30%的佣金参考范围。[论文作者稿](https://arxiv.org/abs/2406.19014)，[期刊DOI](https://doi.org/10.1016/j.trc.2025.105326)。

**我们的建议**：HV佣金主情景暂取该区间中点25%，司机结算75%车费。这是研究者在文献范围内的选值，不是论文实测均值，更不是滴滴西安2016合同。参考范围保留在配置里，不因此启动参数网格。该文部分算法例子使用的其他佣金值，也不能冒充商业抽成校准。

若最后采用的制度不是“平台自营AV、司机承担HV车辆成本”，必须重新写现金流归属；不能只改一个系数。

### 2.2 车辆成本：从原始分项推导，不拿全成本结果当边际成本

Becker等的跨城市研究包含北京和重庆；Table A.4—A.6提供车辆分项及技术/车队修正，Table A.8提供清洁费，Table A.10的中国换算率为6.644 CNY/USD（2016汇率）。这些是论文成本假设，不是我们城市的测量值。[发表原文](https://doi.org/10.1016/j.tra.2020.04.021)。

以下仅推导自动化电动车的**四项变动成本小计**。以北京锚点为例，按独立比例修正相乘计算：

| 分项 | 原始值及修正 | 本文推导值（元/车辆公里） |
|---|---|---:|
| 能源 | 0.057 USD/km × 0.90 × 0.95 × 0.90 | 0.291416 |
| 维护 | 0.018 USD/km × 0.65 × 0.75 | 0.058301 |
| 轮胎 | 0.009 USD/km × 0.90 × 1.20 × 0.75 | 0.048435 |
| 电池损耗 | 0.041 USD/km | 0.272404 |
| 小计 | 四项相加，再统一币种 | **0.670556** |

平均清洁费由4.52 USD/次、每40单一次推导为**0.750772元/完成订单**。这是平均摊销代理，不是每单都实际清洗。北京与重庆的上述原始分项相同，但能源修正不同；按重庆锚点计算，小计为0.434185元/车辆公里。两者是情境参考，**不是统计置信区间，也没有用于筛选有利实验结果**。

这些计算是本项目的迁移推导，不是论文报告的“西安AV单公里总成本”。论文采用的未来规模化技术价格，也不能被描述为2016已经实现的商业AV成本。2016汇率口径不等于全部输入均采自2016，未做通胀校准。

### 2.3 固定成本与全成本边界

Bösch等的成本分析适合帮助分开车辆、运营与价格层次；其瑞士金额不直接移植到西安。[Transport Policy原文](https://doi.org/10.1016/j.tranpol.2017.09.005)。

我们的核算边界如下，这是建模选择，不是假称文献已经替我们确定的合同：

- 四项小计**不包括整车/自动驾驶硬件折旧、保险、停车、平台管理、远程协助及税费**，不能称为总运营成本或净利润。
- 整车折旧若按里程体现使用损耗，可以作为增量费用；若按持有时间体现，则按资产/车时核算。同一部分不能两边都扣。本轮不凭一个购车价直接定这两个口径。
- 电池损耗已经单列，后续整车折旧需排除重复电池摊销。
- 固定车时下、与分派无关的共同开支可不影响策略排序，但应在完整收益报告中列明。不能因此声称这些支出不存在。
- 当前851个C单元是班次槽位，不是851辆独立资产，不能据此计算整车购置和折旧总额。
- 不把拥堵、交叉口复杂度、Stage3暴露度再次随意折成货币罚分。道路适配首先保持既有资格逻辑；时间占用通过服务时长与未来机会体现。

## 3. 建议采用的现金流写法

设同一订单的统一情景车费为F，平台佣金比例为α，AV完整接驾/载客距离为d_p、d_l。以下把待定费用保留为符号：

\[
m_H=\alpha F-b_H-c_{plat,H},
\]
\[
m_A=F-c_A(d_p+d_l)-\kappa_A-c_{assist,A}-c_{usage,A}-c_{plat,A}.
\]

这里c_A目前只有上述四项锚定小计，κ为平均清洁费，b_H为平台额外支付的司机补偿。尚未定值的项目不能在实现时把null自动读成0。若研究决定排除某项，应显式写“模型不含该项”及适用结论，不能写“该项真实成本为零”。

所有方法用同一套车费、佣金和费用归属；C/M/A也不因能力等级自动改变车辆成本。HV司机自付的能源/损耗不能在司机结算之后再从平台收益扣一遍。实际接驾、调位、完整载客行程各记一次，不再套一个文献空驶率，避免重复计算。

两类车平台费用相同、且没有额外司机补偿时，当单AV优势满足：

\[
(1-\alpha)F>
c_A(d_p+d_l)+\kappa_A+c_{assist,A}+c_{usage,A}.
\]

这不是“AV一定更优”：AV接驾更长、能力不兼容、被当前订单占用后错失后续任务，都可能改变联合规划选择。未来机会已进入联合目标时，不另塞一笔没有来源的“AV闲置惩罚”。

## 4. 哪些参数已经有依据，哪些尚未确定

| 项目 | 当前处理 | 是否可称实测校准 |
|---|---|---|
| HV佣金 | 建议25%，文献参考20%—30%，属于区间内研究选值 | 否 |
| AV四项变动成本 | 保存两城市锚定推导；正式使用的城市/单值尚未选定 | 否 |
| 平均清洁费用 | 文献频率与单次费用的推导代理 | 否 |
| 统一车费F | 尚未赋值，不能自动沿用旧8+2d+0.4t | 否 |
| 整车使用折旧、保险等 | 保留类别及待定字段，不重复分摊 | 否 |
| 远程协助/安全员 | 当前无可直接迁移的费用依据；未定值，不默认免费 | 否 |
| 额外司机接驾补偿 | 合同尚未确定，不沿用按策略名称变化的旧公式 | 否 |

本轮没有找到足以确认**西安2016滴滴统一车费合同**的一手原始记录。其他城市/年份的网约车费率、巡游出租车运价不能被悄悄替换为这份数据的实际车费。之后可以选择有明确原始来源的参考费率，或作者明确给定的统一研究费率；两者都须标明迁移边界。

## 5. 接下来只做必要工作

1. 确定统一车费及平台/HV结算制度，并明确是否只研究“扣除已建模变动费用后的贡献”，还是需要补齐更完整的成本账。
2. 在运行前固定一个经济主情景：每项写来源、原始单位、换算、承担方和排除项。不用已有AV利用率或Test31结果选择参数。
3. 再接入统一账本与联合优化。保留当前服务保障、300秒接单期限、600秒接驾上限及原资源预算；不新加费用参数扫描或全天实验。

这不是新增一轮大审计，而是避免把“假设的AV成本优势”写成“由订单数据识别的真实利润优势”。
