# 固定三组全天结果：执行可用，前瞻优先未带来总体收益

## 1. 最重要的结论

两层方案已跑完三个连续全天，解决了旧实时全链反复中途退出的问题。在固定C、AV计划车时水平0.1、P70和300秒耐心下，单组含加载实测30.62—47.14分钟，峰值1.19—1.20GiB。工程可用不等于方法效果已被证明。

**本次应保留“当前服务优先”作为主控制候选。** 同一能力布局下，联合续行价值比当前服务优先少完成392单（−1.382个百分点）；C多服务20单，但HV少服务412单。不能写成总体服务提升，也不能据此把损失全部归因于C的物理能力。

能力布局相对热门布局只多完成100单（+0.353个百分点），是小幅描述性差异，尚不足以证明重型能力布局具有强优势。原三组全部完成后停止，不为追求正结果补跑或调整参数。

## 4. C车辆为什么仍然服务较少：现有记录能说明什么

9,275个订单载客路线满足当前C定义，P70后仍有6,534个C可接受订单。在能力布局＋服务优先组，C服务739单，HV服务其中4,896单，其余899单未服务。**因此“根本没有C兼容订单”不能独自解释低产出。**

该组476／851个C班次至少服务一次，175个至少服务两次，最多一次班次6单；C服务／计划C车时约0.602单/小时，HV约2.019单/小时。C客户忙碌时间／计划C车时约11.25%；这是含承诺延时、未计调位的对账比，不是真实在线利用率。

已保留的接驾接口诊断显示：

- 待验证C接驾候选8,619次，保留2,475次（约28.72%）。这些是可能重复的候选arc次数，不是独立订单人数。
- 被接口判定的主要拒绝：掉头规则2,890次、载客／接驾方向端点不连通952次、距共享端点过远892次、无灯movement超出C设定811次；另有环岛285次、历史方向上下文不可用167次等。
- 能力布局增加C候选保留量，但最终C服务只多11单。仅优化上线位置不足以消除后续接驾／连接损失。

可以据此提出：**C的低产出涉及接驾连接、末端接缝、时空位置以及HV对同一订单的竞争，不只是载客路线的静态分类。** 但不能把接口计数直接宣称为现实必然需要掉头，不能把接缝证据不足全部归作真实能力限制。本轮未放宽这些规则、未做新的接口修复或另加实验。
