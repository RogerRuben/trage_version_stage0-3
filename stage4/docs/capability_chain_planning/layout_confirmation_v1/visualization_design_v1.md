令I_v为供给窗口与本地日历日[0,86400)的交集，H_C为这些C窗口的总小时。主指标：

\[

### 3.2 A面板：资源位置不是行驶轨迹

对保存的上线位置键j定义：

\[
W_s(j)=\sum_{v:\,b_s(v)=j}|I_v|/3600,\qquad
\Delta W(j)=W_J(j)-W_H(j).
\]

位置来自placements中的site_id、node_id、position。以已有位置身份聚合，不新增路口聚类，不最近邻猜测Stage3节点身份；该node_id也不能未经映射就当OSM node ID。不同位置即使接近也不能默默合并。

窗口小时来自既有供给窗口，不用整日24小时替代。位置差异只是上线配置改变，不是车辆实际调位；不连接起终点箭头冒充行驶路径。全域应满足两方案总H_C相同、所有位置差异之和为零。

### 3.3 B面板：从“通过次数”收紧为“订单路段覆盖数”

令R_o为订单已有的有向路线身份集合，S_s(o)为最终服务者状态C、HV或未服务。定义：

\[
F_C^s(e)=\sum_{o\in\mathcal O}
\mathbf1\{S_s(o)=C\}\mathbf1\{e\in R_o\},\qquad
\Delta F_C(e)=F_C^J(e)-F_C^H(e).
\]

**同一订单同一有向路段只计一次。** 这样一个物理路段对应多个canonical片段时不会膨胀计数；重复经过同一有向边也只表示该订单覆盖过它，不称物理访问次数。正反向仍分开。

本面板是“被服务历史订单的路线足迹”，不是native逐边行驶日志、实测交通流、路段载客时间或安全性。不得将整单时间均摊至边后称道路利用率，也不能将各边覆盖数相加当全队订单数。

身份与几何处理沿用现有解析：FULL_NETWORK_EDGE使用resolved_stage3_edge_uid；历史反向overlay保留独立反向身份和标签，几何可取其明确绑定的physical_forward_stage3_edge_uid并反转，不将计数混进正向边，不由此认定AV方向可路由。UNRESOLVED不做最近邻修补，报告未映射数量；线路缺口不跨接。

整条edge几何仅是路段符号，首尾partial仍属于“覆盖过该路段”，不能把地图称为精确裁剪GPS轨迹。路线引用必须匹配已选路线；已核对当前研究输入中29,864个为ORIGINAL，136个为空。仍需按共同人口和已服务集合核对，不能假定那136个都被排除。

### 3.4 C面板与图注

新增集合G={o:S_H(o)=未服务，S_J(o)≠未服务}；失去集合D={o:S_H(o)≠未服务，S_J(o)=未服务}。C↔HV替换不进入G或D。

使用请求的WGS84起点，不把未服务订单的历史路线画成已执行轨迹。replay_base含三个profile的90,000行，按order_id先确认坐标一致，再去除profile重复；禁止直接join导致点数三倍。重叠点不做地理抖动；可以聚合同一保存位置的数量，不额外吸附到道路。

拟定图注：**初始部署与服务足迹的空间变化。** A为日历日C可接单车时的上线位置差异；B为C完成订单在已有有向路段上的覆盖数差异；C为共同请求人口中的新增与失去服务起点。所有差异为联合布局减兼容热点。路线足迹不代表逐边实际车辆观测，空间共现不识别局部因果效应；缺失身份和位置数量在图注披露。
