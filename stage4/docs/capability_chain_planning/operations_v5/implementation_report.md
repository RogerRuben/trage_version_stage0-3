## 2. 最终候选和连接诊断

`request_decision_diagnostics.py`的类型计数在每次请求进入派单轮时重置“当前轮”字段，生命周期累计量另存。不能用早先曾出现的C候选，宣称最终HV获单轮仍有合法C。

HV获单轮记录：

- 当轮最终AV/HV候选数与各类型最小预测接驾ETA；
- 是否存在最终合法AV候选；
- 这些AV在联合解里是服务其他请求、继续空车移动，还是保持未占用等待。

继续已发出调位的WAIT不是静止空闲。数据只描述已准入的Top-K候选及全局当前选择，不能证明Top-K之外没有机会，也不能证明HV选择错误；服务其他请求的C不能再重复分给该HV订单。

连接拒绝记录保留原平面reason counters，另加有界的“类型:阶段:reason”计数，每请求最多64种分类。接口阶段由完整movement路径跨越边界的位置辨识，不凭单个edge UID猜测；重复发生且无法定位的情况记录`AMBIGUOUS_JOIN_BOUNDARY`，一个movement跨两个接口记`MULTI_INTERFACE_JOIN`。未修改冻结Stage3 parser，只在Stage4复用结果上附加诊断。

## 4. 空驶次级优化的数学保证

先用原编码得到主目标最优流 \(f\)。在其残余图上求节点价格 \(p\)，令

\[
\bar c_{uv}=c_{uv}+p_u-p_v.
\]

价格使所有有残余容量的弧非负。由互补松弛，原弧正reduced cost固定为零、负值固定为上界，只有零值弧可变化。任意同供给可行流 \(g\) 满足

\[
c^\top(g-f)=\sum_e\bar c_e(g_e-f_e)\ge0.
\]

等号要求非零reduced-cost弧保持上述固定值。因此零值弧与剩余节点供给组成完整主最优面，在该面求第二次稀疏最小费用流，保留临界服务、当前服务、carry-over和原近似续行价值的全部主优先级。代码还直接核对四项整数score未变。

这是经典流对偶/互补松弛的应用，不是新定理。[MIT最小费用流讲义](https://courses.csail.mit.edu/6.854/18/Notes/n9-mincostflow.html)、[OR-Tools接口](https://developers.google.com/optimization/flow/mincostflow)

次级费用定义为 \(d_e^{mm}=\operatorname{round}(1000d_e^m)\)。物理距离、路径、ETA与窗口不舍入；若选择N个当前动作，所得真实米数相对该主最优面内真实米数最优值的舍入差不超过 \(N/1000\) 米。此界只在次级求解证明最优时报告，未完成时为null，绝不填一个假误差界。

这样无需用“主目标大整数×全局距离范围”再扩大权重，避免整数范围触发慢速回退。优先使用现有固定CPU流求解器；稀疏整数参考路径保留。预算不足保留已合法主解，并明确次级未证最优；非可中断原生调用超时单独标注，不延长10秒预算或假称按时完成。

保证只适用于当前已准入候选图、当前主优先级和毫米费用，不覆盖Top-K外候选、真实未来、全天服务或利润。类型调位及不同当前配对会改变后续状态，**不能由当轮服务数相同推断全天服务率必然相同**。
