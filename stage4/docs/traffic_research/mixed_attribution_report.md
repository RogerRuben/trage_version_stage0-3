## 结论

**当前C主要限制的是有参考支持的相对减速环境，并非严重拥堵，也不是主要由低支持参考造成。**
2,724个原合格但新增超预算订单中，1,986个（72.91%）属于“relative-MIXED单独超预算，
拥堵+严重拥堵不单独超预算”。2,629个（96.51%）仅计满足原参考支持的环境外贡献仍超预算。

因此本批收紧的是解释：C应称为本研究中“对相对减速也较保守”的情境。
不能把它描述为数据已经证明的“只能在非拥堵道路运行的真实AV能力”。
这些结果没有自动授权修改C，也没有证明现有C适配假设最优。

## 2. Relative-MIXED具体表示什么

定义不变：pace ratio≥1.5，但crawl+stop<0.5。

| 样本 | 预测速度中位数 km/h | 参考速度中位数 km/h | pace比值中位数 | low-speed占比中位数 |
|---|---:|---:|---:|---:|
| Validation25 | 23.53 | 41.43 | 1.669 | 21.33% |
| Validation26 | 23.67 | 41.39 | 1.665 | 20.07% |
| Validation27 | 23.56 | 41.17 | 1.661 | 21.44% |
| Test31全部动态完整路线 | 24.13 | 41.78 | 1.657 | 16.99% |
| Test31 C新增排除路线 | 24.45 | 43.43 | 1.666 | 16.27% |

最后一行含2,644条有relative-MIXED暴露的路线、11,563个token、1,569条有向edge。
并非全部2,724条排除路线都有该暴露。此组stop预测占比的时间加权中位数约0.052%，
满足原支持部分的预测速度P10/P90约20.20/32.13km/h；这些都不支持把整组称为“极端拥堵”。

两类MIXED也不应混为一谈：Validation背景低速型MIXED的预测速度中位数约15.03km/h，
参考速度约17.33km/h，low-speed占比约99.0%；相对减速型却有更快的绝对速度和明显更快的参考。
这说明目前C适配表达的是相对环境变化与低速证据的组合假设，不是“绝对越慢越不适配”的单轴规则。
这些是同一冻结模型的预测输出，不构成两种状态的独立准确率验证。

## 3. 谁真正使C超预算

令R=relative-MIXED占比，G=congested+severe占比；实际超标边界为>0.05+1e-6。
Test31 C原资格通过5,821单中，3,097单通过交通预算，2,724单超预算：

| 互斥归因类别 | 订单数 | 含义 |
|---|---:|---|
| RELATIVE_ONLY | 1,986 | R单独超标，G不单独超标 |
| CONGESTION_ONLY | 115 | G单独超标，R不单独超标 |
| BOTH_INDIVIDUALLY | 437 | R、G各自都超标 |
| COMBINED_ONLY | 186 | 两者各自不超标，但合计超标 |
| 合计 | 2,724 | 不重复计数 |

ONLY表示“仅这一家族足以独立超标”，不表示另一家族暴露为零。
Validation三天RELATIVE_ONLY分别为3,145 / 3,251 / 3,331单，但它们未经过相同Stage4资格过滤，
不能与上述1,986单直接比较为时间趋势。

### 低支持是否主导

原支持规则=至少100个order-days且至少5个日期，仅用于本批分层，未恢复为准入门槛。
在C新增排除路线的relative-MIXED暴露中，低支持时间仅占**0.98%**；
Validation三天全样本relative-MIXED的低支持时间约1.13% / 1.49% / 1.34%。

把全部C环境外暴露进一步拆成满足原支持/低支持两部分，完整路线分母不变：

| 账面归因 | 订单数 |
|---|---:|
| 满足原支持部分单独仍超5% | 2,629 |
| 去掉低支持贡献后不再超5% | 95 |
| 其中低支持部分单独就超5% | 52 |
| 其中两部分合计才超5% | 43 |

这里“去掉”只用于数学分解，没有实际删除token、重归一化分母或重跑策略。
满足原支持不等于真实交通准确；低支持也不等于错误。
本批能排除“主要限制来自低支持贡献”这一解释，但不能排除模型偏差、q20参考含义、
partial-link测量差异或状态阈值本身的影响。

## 4. 已有动态结果怎样与这些类别对应

只重新连接已有F/VT cohort，不启动仿真。F→V在上批逐分配相同，因此这里也对应V→VT的转移。

| Profile / 窗口 | 失去服务订单的归因 | 新增服务 |
|---|---|---:|
| C 10:30 | relative-only 5；both 1；combined 1；交通通过3 | 4（均HV） |
| C 17:30 | relative-only 11；both 5；combined 1 | 2（均HV） |
| M 10:30 | 无 | 0 |
| M 17:30 | 2单均通过M的severe预算，原本由HV服务 | 0 |

### C的AV→HV与AV→未服务

- 上午3个AV→HV订单均为relative-only；4个AV→未服务中，relative-only 2、both 1、交通通过1。
- 晚间8个AV→HV订单中，relative-only 6、both 2。
- 晚间13个AV→未服务订单中，relative-only 7、both 5、combined 1；
  另外4个原HV订单未服务，也都属于relative-only，但HV本身不受这一交通门控。

M晚间2个原AV订单超过severe预算并转由HV服务，同时1个原HV订单转由AV服务；
净失去的2个订单原本是HV服务且通过M交通预算。不能写成“2单被severe直接拒绝”。

**这里观察到的是服务集合重新分配；不是每个订单服务损失的独立因果归因。**
交通预算通过仍可能失去服务，超预算仍可能由HV服务。车辆位置、再次可用和匹配竞争的
完整传播链没有在本批恢复，不能用这些交叉表声称已经量化全部系统中介效应。

### 缺失与路线身份

每个上午cohort有2单、晚间有3单没有动态完整ORIGINAL描述，均保留MISSING，且F/VT都未服务。
全cohort注释的是原历史ORIGINAL路线，不把该状态转投到fallback路线，也不声称所有HV订单
都有AV资格。8个profile/window/variant组合中，全部实际AV服务订单均核对为ORIGINAL且原资格通过。
配对Parquet继承的base_eligible列是C口径；M解释只用severe的actual_gate列。
actual_gate是原路线的交通预算比较，不是包含结构/乘客/耐心/Gamma的全资格结果。

## 5. 对下一阶段的含义

目前最稳妥的是保留研究开关与当前假设，并把C的含义说清楚：其额外限制主要针对
相对经验参考减速的道路暴露，而非只针对严重拥堵。不能为了恢复服务率而自动放宽MIXED。

若研究问题仍严格要求“C=非拥堵、M=拥堵、A=严重拥堵”，则relative-MIXED是否属于C环境外
仍是作者需要明确的情境定义，而不是用当前服务差异就能估计出来的实车能力。
本批不替作者重新选择、不启动统一Gamma/历史状态的跨profile实验。
